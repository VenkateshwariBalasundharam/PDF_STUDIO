# 2. Important Development Principle

Do NOT tightly couple the PDF application to a particular PDF implementation.

Create an abstraction:

```csharp
public interface IPdfEngine
{
    Task<byte[]> GenerateAsync(
        PdfGenerationRequest request,
        CancellationToken cancellationToken);

    Task<byte[]> MergeAsync(
        IReadOnlyList<byte[]> documents,
        CancellationToken cancellationToken);

    Task<byte[]> SplitAsync(
        byte[] document,
        IReadOnlyList<int> pages,
        CancellationToken cancellationToken);
}
```

The rest of the application must depend on the interface.

The PDF engine implementation can be replaced later without changing the API, business layer, UI, or database design.

Prefer Microsoft/.NET functionality where possible.

Do not introduce third-party dependencies without first explaining why they are necessary.

# 31. Development Rules

Follow these rules strictly:

1. Do not create unnecessary microservices.
2. Start with a modular monolith architecture that can evolve into microservices.
3. Keep Public API and Private API logically separated.
4. Keep PDF Engine independent.
5. Keep Storage independent.
6. Keep Database access independent.
7. Use interfaces for replaceable infrastructure.
8. Use dependency injection.
9. Use SOLID.
10. Use clean architecture.
11. Use async APIs.
12. Use CancellationToken.
13. Avoid duplicated code.
14. Avoid hard-coded configuration.
15. Use environment configuration.
16. Never commit secrets.
17. Never expose internal exceptions.
18. Never trust uploaded files.
19. Never allow cross-tenant data access.
20. Add automated tests for critical functionality.
